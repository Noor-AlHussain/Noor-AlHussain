# Setup

For anyone forking or cloning this repo to adapt for themselves — here's
what to run and in what order, and why some files that will exist in the
live version aren't populated yet in a fresh clone.

## Why some assets look empty on first clone

`assets/generated/*.svg` (stats, streak, dashboard, etc.) and
`assets/previews/*.png` are **not committed as empty** — they're populated
by scripts that call the GitHub GraphQL API and a headless browser
respectively. Both need things a fresh clone doesn't have yet: a
`GITHUB_TOKEN`, and either network access or a running local server. Rather
than ship broken image links until the first CI run, this repo ships
on-brand "INITIALIZING" placeholders instead, generated by the two
bootstrap scripts below. `update-readme.yml` and `render-3d-previews.yml`
overwrite them with real data automatically once they run in GitHub Actions
— nothing here needs to be done manually in the actual deployed repo.

## First-time local setup

```bash
npm install

# Generates on-brand placeholder SVGs for anything that needs live GitHub
# API data (dashboard, stats, streak, langs, wakatime, heatmap, snake).
# Safe to run anytime — skips any file that already exists.
node scripts/bootstrap-placeholders.js

# Same idea, for the animated 3D scene preview PNGs.
# Requires Python 3 + Pillow (pip install pillow --break-system-packages).
python3 scripts/bootstrap-preview-placeholders.py

# Builds the skill-universe force-graph data file.
# Pure Node, no external API — safe to run immediately.
node scripts/build-skills-json.js

# Generates the real SHA-256 integrity manifest for the current file set.
node scripts/generate-integrity-manifest.js

# Renders the RESEARCH LOG section of README.md from data/research-log.yaml.
node scripts/generate-research.js

# Validates resume.json — a real jsonresume.org-schema file. Fill in your
# own work/education history before publishing; it ships empty on purpose
# rather than with fabricated entries.
npm run validate:resume
```

## Getting live data (optional, for your own fork)

To replace the placeholders with real GitHub stats locally:

```bash
export GITHUB_TOKEN=ghp_xxxxxxxxxxxx     # a token with public read scope is enough
export GITHUB_USERNAME=your-username
npm run generate:all
```

## Running the test suite

```bash
npm test              # vitest unit tests
node tests/visual-regression.js   # pixelmatch — creates tests/baselines/ on first run
sha256sum -c assets/integrity-manifest.asc   # verify the manifest itself

# Real cryptographic provenance check (only works after the real repo has
# run update-readme.yml's attestation step at least once — needs the gh CLI
# and network access, won't work offline):
gh attestation verify assets/integrity-manifest.asc --repo Noor-AlHussain/Noor-AlHussain

# Lighthouse CI — accessibility/best-practices/SEO/performance audit
# against the assembled dist/ build (see .github/workflows/lighthouse-ci.yml
# for exact dist assembly steps):
npm install -g @lhci/cli@0.15.x
lhci autorun
```

## Adapting this for yourself

If you're forking this as a starting point rather than just reading it:

1. Replace every `Noor-AlHussain` / `NoorHack` string across `README.md`,
   the `assets/portal/` files, and the workflow files with your own handle.
2. Regenerate `data/research-log.yaml` with your own entries — the template
   entries describe tools that exist in *this* repo; delete or replace them.
3. Re-run `node scripts/generate-integrity-manifest.js` after any changes —
   a stale manifest that doesn't match the actual files is worse than no
   manifest at all.
4. See `LICENSE` for what is and isn't covered if you reuse the code —
   note that `assets/canvas/rust-engine/` is GPL-3.0-or-later, not MIT
   like the rest of the repository; see its own `LICENSE` file.
