Each point = average steps for 30 random 3-SAT formulas at that variable count (ratio ~4.2 clauses/variable — the hardest region near the phase transition).

What DPLL does: it picks an unassigned variable, tries true, propagates the consequences through unit propagation, and recurses. If it hits a contradiction it backtracks and tries false. That branching is where the exponential comes from: worst-case 2ⁿ nodes in the search tree for n variables. The tree you see above is that search trace.

Why this connects to P vs NP: SAT was the first problem proven NP-complete (Cook–Levin, 1971). Every NP problem — graph colouring, circuit satisfiability, protein folding, integer factorization as a decision problem — can be reduced to SAT in polynomial time. If anyone ever found a polynomial-time SAT solver, P would equal NP and virtually all of modern cryptography would collapse: RSA, elliptic curves, hash commitments — all of it depends on the hardness of problems reducible to NP. Nobody has proved P ≠ NP, but nobody has found a polynomial algorithm for SAT either, despite intense effort since 1971.
