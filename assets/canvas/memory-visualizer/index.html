This is a simulated stack layout built entirely from JavaScript arrays — no real process memory is read, written, or executed at any point. It exists to make a textbook security concept visible, the same way a CS:APP diagram does, not to demonstrate an exploit technique.

What's actually happening: a fixed-size local buffer (char buf[8] in C terms) sits below the stack canary and the saved return address in this simulated frame — exactly the layout a real x86-64 stack frame has with stack protection enabled. Drag the slider past 8 bytes and watch the write spill upward into the canary, then into the return address.

In a real process, a corrupted canary triggers __stack_chk_fail and aborts before the function returns. A corrupted return address — if the canary is bypassed or absent — is what redirects control flow on return, which is the entire premise of classic stack-smashing. Nothing here executes; it's the bookkeeping diagram, not the technique.
