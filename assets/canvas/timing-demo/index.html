Run the benchmark to see measured timing per guess.

What this measures: for each guess, this page actually times 20,000 repeated comparisons against the real secret string, in your browser, right now — these aren't fabricated numbers. The naive comparison returns as soon as it finds a mismatched character, so a guess that's correct for longer takes measurably more time. The constant-time version always walks the full length and XORs every byte before checking the accumulated result once at the end, so its timing stays flat regardless of where the mismatch is.

This is the entire reason libraries expose functions like crypto.timingSafeEqual (Node.js) or hmac.compare_digest (Python) instead of letting you write a === b on secrets: an attacker who can measure response time over enough requests can recover a token or password one character at a time, never needing to guess the whole thing at once.
